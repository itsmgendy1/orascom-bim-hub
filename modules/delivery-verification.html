▶ ⚙ As-Built Validation Rule — how a drawing's currency is checked against its Revit model

A drawing is PASS when its Revit model's Last updated calendar date equals the drawing's Last updated date (hours/minutes ignored), and PASS — MODEL NEWER when the model date is later — the model is current relative to the drawing. It is FAIL — MODEL OLDER when the model date is earlier than the drawing date — the drawing may have been produced from a newer model state than what is currently filed. A record is NO MODEL / AMBIGUOUS MATCH whenever the building, discipline, or matching Revit model cannot be reliably determined — this tool never guesses.

Building is read from the folder path segment that immediately follows the project's "LOD" folder (e.g. "01. LOD 500"). Discipline is read from the folder segment under Drawings/DWG or Drawings/PDF; for Revit models — which sit in a flat "Revit models" folder with no discipline subfolder — discipline is inferred from the file name's discipline code, using a mapping learned automatically from this project's own drawing file names (shown in Provenance below, not hard-coded). Drawings are matched to a Revit model by Building + Discipline; when more than one model matches, the file name's level/zone code is used to disambiguate — if it's still ambiguous, the record is marked AMBIGUOUS MATCH rather than guessed.

When a building has no model for a discipline, an auditable cross-discipline fallback is tried in the same building only (WS/DR↔PS, LI/SS→EL, FA→EL/TE, AV→TE, ME/LPG→WS/PS). Records resolved this way are labelled "Matched via discipline fallback WS→PS" in the Result column, counted in Provenance, and exported — never silently substituted. The Validation Details tab also offers a 📋 Brief grouped view (one row per building + discipline + model with drawing counts and date ranges); click a brief row to drill into its full records.
